# Ponytail (GitHub repo)

> [raw source](../../raw/2026-09-26-ponytail.md) · Dietrich Gebert · code repo
> (README and core skill files, v4.10.0). **Playbook: [[ponytail]].**

## TL;DR
An MIT-licensed plugin and skill set for about 20 AI coding agents. It makes the
agent act like a "lazy senior dev": climb a seven-rung ladder (YAGNI → reuse → stdlib
→ native → installed dependency → one line → minimum) before writing code, while
never cutting validation, security, data-loss handling or accessibility.

## Key takeaways
1. **The ladder** is the core idea. It runs *after* the agent understands the
   problem, not instead of it. "Lazy about the solution, never about reading."
2. **Three levels:** lite (suggests), full (enforces, the default) and ultra (deletes
   first and challenges requirements).
3. **Companion skills:** review (diff), audit (whole repo), debt (collects shortcut
   comments), gain, help.
4. **Benchmark:** −54% code, −20% cost, −27% time against a no-skill agent, with
   safety intact. The cuts are largest where agents over-build (date picker: 404 → 23
   lines).
5. **Honest caveats:** one model, n=4, self-run; an earlier "80–94%" figure was
   corrected after a public critique.
6. **Bug fixes = root cause:** check every caller first, and fix it once in the
   shared function.

## Notable claims
- "The rule was never 'fewest tokens.' It is: write only what the task needs, and
  never cut validation, error handling, security, or accessibility."
- "ponytail keeps every safety guard while a bare 'write one-liners' prompt drops one."
- "Lazy code without its check is unfinished." Non-trivial logic leaves one runnable
  check behind.
- On GPT-5.5, a terse reasoning model can end up spending more.
